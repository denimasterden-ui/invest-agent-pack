# agent-run — операторские инструменты для v2

Инструменты **вокруг** агента, не его код. `agent/` — код среза SPC-008, его
трогает следующий срез; здесь то, чем прогоняют бумагу руками.

Зачем нужны: слой 1 намеренно не ходит в сеть (принимает готовые факты и
первым делом проверяет их на когерентность), а слой 2 не генерирует форки
(`fork.evaluate` принимает готовый ответ модели). Эти три скрипта закрывают
разрыв между «есть тикер» и «есть форки».

## Прогон бумаги целиком

```bash
cd invest-dashboard

# 1. факты из yfinance — что не знает, помечает как незаполненное
python3 agent-run/collect_facts.py KSPI -o /tmp/kspi.json
#    ВПИСАТЬ вручную: dps_declared (объявленный вперёд дивиденд — только из
#    отчёта, yfinance знает лишь выплаченный) и сверить shares с отчётом

# 2. сопоставимые — состав берётся из профиля бумаги
python3 agent-run/collect_peers.py KSPI -o /tmp/kspi-peers.json

# 3. профиль (слой 0)
python3 -m agent.cli profile KSPI

# 4. базовая линия (слой 1)
python3 -m agent.cli baseline KSPI --facts /tmp/kspi.json \
  --rate 0.17 --growth 0.09 \
  --rate-why "ставка ЦБ РК плюс премия за риск" \
  --growth-why "инфляция плюс реальный рост"

# 5. форки моделью (слой 2) — с полосой сопоставимых на входе
python3 agent-run/gen_forks.py KSPI --facts /tmp/kspi.json \
  --peers /tmp/kspi-peers.json \
  --rate 0.17 --growth 0.09 --rate-why "..." --growth-why "..." \
  -o /tmp/kspi-forks.json

# 6. посчитать форки доверенным кодом
python3 -m agent.cli fork KSPI --facts /tmp/kspi.json \
  --rate 0.17 --growth 0.09 --rate-why "..." --growth-why "..." \
  --answer /tmp/kspi-forks.json
```

Для НЕбанковских мер вместо `--facts` идёт `--assumptions` (JSON допущений
DCF), см. `agent/eval/fixtures/golden_cases.json` — там образцы обоих видов.

## Что важно знать

**Ставку и рост объявляешь ты, а не модель.** Это ручки, о которых имеет
смысл спорить: `--rate` для банка — стоимость капитала в валюте отчётности,
`--growth` — устойчивый рост. Обоснование (`--rate-why`) уходит в вывод и
остаётся с оценкой.

**Дивиденд — объявленный вперёд, не выплаченный.** На KSPI разница между
8.72 и 5.74 USD даёт половину оценки. `collect_facts.py` оставляет поле
пустым намеренно.

**Отказ слоя 1 — это результат, а не сбой.** Рассогласованные факты
(разные валюты, EPS не сходится с прибылью, устаревший период) остановят
расчёт до числа и скажут, что запросить из отчётности.

**Полоса сопоставимых не строится, если данные грязные.** У банков-ADR
отчётность в локальной валюте против котировки в USD — слой честно
откажется вместо мусорного якоря.

## Что уже ловилось на живых прогонах

**Баланс из yfinance устаревает.** На KSPI 30.08 отдавался FY2025 при
доступном 2К26 — слой 1 отказался считать и назвал период, который нужен.
Поле `period_end` правится руками по свежему отчёту.

**Модель путает валюту.** Первый живой прогон дал `dps_forward = 8.0` в
долларах при отчётности в тенге — коридор вышел 0.32 USD вместо ~120.
Генератор теперь называет валюту отчётности и порядок величин в промпте, а
проверка направления форка ловит остаток («bull ниже базовой линии на 100%»).

**Модель выбирает недоступный канал.** Для банка канал «поток» не считается —
предпосылок потока у меры `ddm_ri` нет. Генератор теперь говорит модели,
какие каналы доступны для этой меры.

**Модель путает поля якоря.** `own_history` вместе с `confirms=estimate` —
класс называет источник, а признак говорит, что источника нет. Слой
отклоняет: одно из двух неверно.

## Расход

`gen_forks.py` — один вызов модели по текущему провайдеру (`config.provider()`).
Остальное считает код локально, без сети, кроме походов в yfinance за
котировками.
