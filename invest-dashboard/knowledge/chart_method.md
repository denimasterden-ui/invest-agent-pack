# Разбор графиков материала — бриф субагента-измерителя

**Самодостаточный бриф для субагента** (Шаг 2.5 `investagent-run`, когда материал —
`.mhtml` с картинками). Задача: вытащить с графиков материала числа, **измеренные
кодом**, а не прочитанные с картинки глазами. Разброс «на глаз» между прогонами —
проценты (35%/40% на одном графике против измеренных 39.8%); измерение скриптом
воспроизводимо by construction. Раньше эту роль играл codex-агент; теперь —
Claude-субагент с изолированным контекстом (собирает у себя, возвращает только
готовую секцию).

Даётся субагенту: тикер, путь к `.mhtml`. Возвращает: секцию «ГРАФИКИ МАТЕРИАЛА»
(формат внизу). Работай в фоне — измерение медленное (~175с/график).

## Шаг 1 — выгрузка картинок-кандидатов
```bash
$IA images ПУТЬ-К.mhtml -o /tmp/ТИКЕР-imgs
```
Выгружает уже отобранные «статейные» картинки (`knowledge._mhtml_image_candidates` —
отбор не пересматривается: аватары/трекеры/реклама отсеяны) в PNG + манифест.

## Шаг 2 — классификация (по одной)
Открой каждую картинку, определи тип:
- **chart** — график/диаграмма с данными (линии, бары, точки, срезы);
- **table** — таблица с числами;
- **photo/logo/other** — фото, логотип, скриншот текста/интерфейса.

В разбор идут **только chart/table**; photo/logo/other отбрасываются. Доверяй
**типу**, не «полезности»: цена ошибок несимметрична — лишнее измерение стоит один
проход, потерянный график теряет данные. Не понял тип — пропусти, не трактуй наугад.

## Шаг 3 — измерение (chart/table) — КОДОМ, не глазами
Для каждой chart/table в **отдельном пустом временном каталоге** (картинку скопируй
туда):
1. Напиши `measure.py` и запусти `python3 measure.py` (Pillow и numpy стоят). Схема:
   **найди линии сетки** по цвету/яркости → **откалибруй оси линейной регрессией** по
   найденным линиям → **найди центры фигур** (бары/точки/сегменты) → переведи пиксели
   в значения осей.
2. Числа бери **из вывода скрипта**. Называть значение «на глаз», когда сетка для
   калибровки есть, — **запрещено**.
3. Калибровка невозможна (таблица-скриншот, график без осей/сетки) — читай видимые
   числа глазами, помечай каждое `eye`.

Итог одной картинки — JSON:
```json
{"kind": "chart|table", "title": "что на картинке, до 10 слов",
 "measured": [
   {"label": "P/Bv 2024", "value": "3.9", "how": "script", "note": "калибровка по 7 линиям сетки"},
   {"label": "Выручка 2025", "value": "1903 млрд ₽", "how": "eye", "note": "таблица без сетки"}
 ]}
```
`how`: `script` — посчитал скрипт из пикселей; `eye` — прочитано глазами. `how` вне
{script,eye} = eye (точность скрипта нельзя приписывать числу, которое им не
получено). Пункт без `label`/`value` выбрасывается — число без имени бесполезно.
Полезных чисел нет — пустой `measured`.

## Устойчивость
Сбой ОДНОЙ картинки (таймаут, ответ не по схеме) **не теряет разбор**: пометь её
причиной в секции, остальные разбирай дальше.

## Формат возврата (секция для синтеза)
```
=== ГРАФИКИ МАТЕРИАЛА (числа измерены кодом, не прочитаны с картинки) ===
Кандидатов: N · измерено: M · отсеяно (photo/logo/other): K [· сбои, если были]

#### 1. chart — заголовок
- P/Bv 2024: 3.9 — измерено скриптом (калибровка по 7 линиям сетки)
- ROE 2024: 40.4% — измерено скриптом
#### 2. table — заголовок
- Выручка 2025: 1903 млрд ₽ — прочитано глазом (таблица без сетки)
```
Каждое число помечено **«измерено скриптом»** или **«прочитано глазом»** — пометка
сохраняет происхождение при вставке в синтез.

## Куда идут числа
Это **контекст/кросс-чек** аналитику, не прямой вход в расчёт. В `ingest` каждое
число ложится под якорь по [лестнице надёжности](research_method.md): график из
отчёта эмитента → `company_guide`/`own_history`; «измерено скриптом» — самое сильное
подтверждение (воспроизводимо). Где измеренное расходится с текстом материала —
**назови конфликт явно** (вход для `ingest.compare`).
