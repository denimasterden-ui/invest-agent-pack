# Методология ресёрча — бриф субагента-ресёрчера

Этот файл — **самодостаточный бриф для субагента-ресёрчера** (Шаг 2.5
`investagent-run`). Ресёрч делегируется субагенту с ОТДЕЛЬНЫМ контекстом: он
собирает сырьё web-поиском у себя, а в основной контекст возвращает только
готовый синтез — так основной прогон не засоряется сырыми результатами (раньше
эту роль изолированного контекста играл Perplexity-провайдер, теперь — субагент).

Дать субагенту: тикер, имя, валюту отчётности, `research_type`, и — если есть —
человеческий материал (см. ниже). Просить вернуть синтез по блокам A/B/C ниже,
на русском, с якорем-датой на каждой цифре. Тот же бриф годится и для инлайн-
ресёрча, когда субагент не нужен.

**Recency — первое правило.** Отчитывайся по САМОМУ СВЕЖЕМУ опубликованному
кварталу, не по чаще всего цитируемому. Префикс квартала на каждой цифре
(«Q2 2026: …»). Если свежайший проверяемый квартал старше ~4 мес — скажи явно
сверху, а не выдавай устаревшее за текущее: неверное направление тренда опаснее
пропущенного числа. Игнорируй рейтинги аналитиков и price targets — это
сентимент, не фундамент. Только факты, меняющие внутреннюю стоимость.

**Надёжность источника — второе правило.** Веди **каждое число к источнику,
который им владеет** (эмитент для своей отчётности, не блог, его цитирующий).
Респектабельная пресса не «понижает» число, если она цитирует primary —
тегай нижележащий primary. Тир источника → класс якоря (`anchor_class`), под
которым число потом ложится в канон и проходит гейт:

| тир | что | anchor_class |
|---|---|---|
| 1. Эмитент-primary | 10-K/10-Q/20-F/8-K, пресс-релиз, earnings-дек/транскрипт, IR | `company_guide` / `own_history` |
| 2. Регулятор / макро | ЦБ, статведомства, биржевые филинги | `macro_guidance` |
| 3. Peer-primary | филинги конкурентов для peer-статистики | `peer_stats` |
| 4. Пресса, цитирующая primary (BBG/Reuters/FT) | мост к primary — тегай primary | (как у primary) |
| 5. Аналитик-ноты / price targets / форумы | сентимент, не фундамент | `analyst_judgement` — числа на этом не якорить |

На каждой цифре синтеза указывай тир/источник — это прямой вход для якорей
`ingest` (число без владеющего источника гейт отклонит).

## Блок A — фундамент (последний квартал)
1. **Операционные вехи** (90 дней) — новые мощности, ДЦ, заводы, контракты,
   крупные клиенты, запуски. Конкретные числа: МВт, GPU, ТБ, единицы, $ контракта.
2. **Финансовые результаты** — выручка, FCF, EBITDA, маржа vs пред. квартал и г/г.
   Что beat/missed и почему важно для долгосрочной модели.
3. **Спрос и pipeline** — backlog, утилизация мощностей, концентрация клиентов,
   листы ожидания. Цитаты менеджмента.
4. **Капиталлокация** — capex, привлечения, изменения долга, байбэки,
   инсайдерские покупки/продажи (объём + plan vs discretionary).
5. **Конкурентные и технологические риски** — новые входящие, ценовое давление,
   устаревание технологии, регуляторные угрозы. Конкретно: кто, что, когда.
6. **Гайденс менеджмента** — явные числовые ориентиры на квартал/год.

## Блок B — археология цены (catalyst-timeline, 12 мес)
Все события, двинувшие цену ±5%+. На каждое: точная дата (YYYY-MM-DD); тип
(court_ruling / earnings / contract / regulatory / macro / management / other);
краткое описание (≤80 симв); направление (up/down); примерный % движения.
**Не пропускай негативные** — срезанный гайденс, проигранные суды, потерянные
контракты особенно важны. Всегда включай последний отчёт и реакцию рынка.

## Блок C — near-term (моментум + катализаторы 90 дней)
- **30 дней аномалий** — новости/слухи под необычный объём, institutional
  buying/selling, block trades, short interest, upgrades/downgrades С ПРИЧИНОЙ.
- **Катализаторы 90 дней** — дата следующего отчёта + консенсус (revenue/EPS),
  запуски, регуляторные решения/суды, investor days, index rebalancing/ETF-потоки.
- **Секторный моментум** — что движет сектор (2 недели); для КЗ/HK — потоки,
  policy-сигналы, макро.

## Человеческий материал — приоритет
Если по бумаге есть human-source (разбор аналитика, `.mhtml` через
`knowledge._mhtml_to_text`) — трактуй его факты как **primary** наравне с web.
Сохраняй его конкретные числа; где web конфликтует — **назови конфликт явно**
(это вход для `ingest.compare`: сверка чисел материала с baseline).
