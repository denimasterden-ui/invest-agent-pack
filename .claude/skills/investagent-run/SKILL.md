# Скилл: прогон бумаги через агента v2

Четыре слоя, каждый со своей ролью: **профиль** (тип бизнеса решает меру),
**базовая линия** (оценка мерой из профиля), **форк** (тезис о будущем как
ветка базовой линии), **идея** (ставка на форк).

Код агента — `agent/`, операторские обвязки — `agent-run/`. Всё зовётся через
обёртку **`agent-run/ia`** (она берёт venv 3.12 из `INVEST_PY` и цепляет токен),
из корня `invest-dashboard`. Прямой `python` не нужен.

**Решение за Денисом.** Скилл считает и показывает; ставку, рост и выбор
форка объявляет он. Числа без якоря агент считает, но помечает — не выдавать
их за доказанные.

## Запуск — обёртка `ia` (одна точка входа)

Прогон копит сущности (профиль, baseline, форки, материалы) в **центральном
каноне**. Всё идёт через обёртку `agent-run/ia` — она берёт python-venv,
`INVEST_MCP_URL` (эндпоинт канона), `INVEST_AUTHOR` (твоё имя-атрибуция) и
`INVEST_TOKEN` (доступ) и зовёт `agent.cli`. Один разрешённый в
`settings.local.json` путь → **скилл не спрашивает подтверждение на каждый шаг**.

Настройка окружения — один раз, см. `SETUP.md` в корне пака:
```bash
export INVEST_MCP_URL="https://<канон-хост>/sse"   # эндпоинт центрального канона
export INVEST_AUTHOR="твоё_имя"                     # атрибуция в каноне
export INVEST_TOKEN="<твой_токен>"                  # доступ (когда включена авторизация)
export INVEST_PY="$HOME/.venvs/invest312/bin/python" # твой venv 3.12 (иначе автодетект)
IA=./invest-dashboard/agent-run/ia
```

`$IA <подкоманда>` = `agent.cli <подкоманда>` (profile/show/baseline/fork/drift…),
плюс `$IA facts ТИКЕР` и `$IA peers ТИКЕР` — обёртки над collect_facts/
collect_peers. Без `INVEST_MCP_URL` = локальный SQLite-фолбэк, центральный канон
не трогается.

## Шаг 0 — инвентарь (что уже накоплено по бумаге)

```bash
$IA show ТИКЕР
```

Одним экраном из канона: мера и версия профиля, драйверы, сопоставимые,
пробелы; последний baseline-коридор; активные форки (последний на лейбл);
разобранные материалы с авторами; число точек дрейфа. Это замена «зайти в
`runs/ТИКЕР` и прочитать README» — вся раскладка теперь на сервере. Начинай
прогон с него: видно, есть ли уже профиль/материал/оценка и от чего плясать.

Форки хранятся append-only: пере-прогон копит поколения, `show` и
`get_scenarios` показывают **последнее на лейбл** (старые — в истории таблицы).

**Детализация:** `$IA show ТИКЕР --detail` — полная раскладка из канона:
допущения baseline (ставка/рост/fcf), по каждому форку тезис + условия
(must_be_true) + override'ы с якорями и источниками, и **полный синтез
материала** (что было найдено в ресёрче). Всё это хранится в каноне; `--detail`
его достаёт.

## Шаг 1 — профиль (что это за бизнес)

```bash
$IA profile ТИКЕР
```

Показывает меру, драйверы, потолки роста, сопоставимых и **пробелы данных** —
то, чего в автоисточнике нет и что придётся вписать руками. У холдинга
профиль составной: мера снаружи (`sotp`), драйверы и сопоставимые от
основного бизнеса.

Мера не та, что ожидалась — не подгонять. Смена меры требует подтверждения
человеком (`cli.py set` → `confirm`), это решение уровня «меняет результат
сильнее любого допущения внутри метода».

## Шаг 1.5 — охват, мера и comps (гейты SPC-016 + SPC-017)

**Посмотри на ВЕСЬ бизнес, а не на яркий сегмент.** У холдинга с расходящейся
экономикой (прибыльное ядро + убыточные/инвестиционные арм) один смешанный
поток занижает ядро, а comps одного сегмента искажают полосу. Не по умолчанию
`levered` — осознанный выбор.

1. **Выложи сегменты** (охват): выручка/маржа/роль (core/growth/optionality)
   по каждому материальному сегменту, из ресёрча:
   ```bash
   $IA set ТИКЕР segments '[{"name":..,"revenue_share":..,"role":"core","note":..}, ...]'
   $IA confirm ТИКЕР <id>
   ```
2. **Выбери меру** (это решение человека): `levered` (blended) vs `sotp`
   (ядро-DCF + чистый кэш + стейки раздельно). SOTP — для холдингов (CLAUDE.md).
   Подтверждение scope **само переключает** `profile.measure`:
   ```bash
   $IA set ТИКЕР scope '{"measure":"sotp","reason":"почему так"}'
   $IA confirm ТИКЕР <id>    # → profile.measure становится sotp
   ```
3. **comps — два разных понятия, оба обязательны** (гейт SPC-017):
   - **head-comps** — аналоги ВСЕЙ компании / основного узла. Непусты **всегда**,
     при любой мере. Пустые head-comps → `baseline`/`fork` отказывают.
   - **part-comps** — по КАЖДОМУ сегменту (робо↔робо, авто↔авто, IoT↔IoT), только
     для `sotp`. У сегмента без публичных аналогов — **private/pre-IPO** сравнимые
     (venture-оценка), помечай `kind:private`:
     ```bash
     $IA set ТИКЕР comps '[{"name":"BYD","segment":"авто","kind":"public"},
                           {"name":"Figure AI","segment":"робо","kind":"private","valuation_ref":"..."}]'
     $IA confirm ТИКЕР <id>
     ```
   **Неясно, кто comps → остановись и спроси Дениса.** Не брать заголовочные/
   пустые: от comps зависят SOTP-оценка частей и base-цена, не говоря о форках.

**Два гейта на этом шаге (отказ = результат):**
- SPC-016 (охват/мера): ≥2 сегмента и мера не выбрана+подтверждена → отказ
  «выберите меру … подтвердите scope».
- SPC-017 (целостность ресёрча под меру): не покрыт узел контракта меры (head-comps
  пусты / сегмент без comps / нет материала под текущую меру) → отказ называет
  **недостающий узел**. Смена меры сама делает материал под старую меру
  недостаточным → триггерит ре-ресёрч (см. Шаг 2.5, `--for-measure`).

Кейс Xiaomi (2026-09): без гейтов — `levered` + comps только авто, разбор тонул
в авто-убытках; с гейтами — форсирован SOTP (ядро смартфоны×AIoT + сервисы
76.8% GM + кэш + опционы EV/робо), а пустые comps + неякорный стейк дают честный
отказ с перечнем сегментов, по которым нужны сравнимые.

## Шаг 2 — факты

```bash
$IA facts ТИКЕР --out /tmp/ТИКЕР.json
```

Скрипт честно печатает, чего не знает. **Обязательно вписать руками:**

- `dps_declared` — объявленный вперёд дивиденд. В yfinance его нет по
  определению, только выплаченный. На KSPI разница 8.72 против 5.74 USD —
  половина оценки;
- `period_end` — yfinance регулярно отдаёт прошлый год. Сверить с последним
  отчётом;
- `shares` — сверить с отчётом, у ADR бывает коэффициент представления.

## Шаг 2.5 — ресёрч (делегируй субагенту) + свежий отчёт

Ресёрч делай **субагентом-ресёрчером с изолированным контекстом** по брифу
`invest-dashboard/knowledge/research_method.md` — он собирает сырьё веб-поиском у
себя, а в основной контекст возвращает только готовый синтез (прогон не
засоряется сырыми результатами). Дай субагенту: тикер, имя, валюту отчётности,
`research_type` и — если есть — human-material; проси синтез по **Блокам A/B/C**
(фундамент по 6 осям + гайденс менеджмента; catalyst-timeline 12 мес;
моментум/катализаторы 90 дней), на русском, с **тиром/источником на каждой
цифре** (лестница надёжности из брифа → прямой вход для якорей `ingest`).

Свежий отчёт — часть Блока A и **обязателен**: проверь
`price_context.earnings_data_stale`; если `true` — вышел отчёт новее стейтментов,
и без его разбора гейт SPC-015 не пропустит `baseline`/`fork`. Это не остановка
на Дениса, а твоя работа как аналитика.

**Материал — `.mhtml` с графиками?** Запусти **отдельным фоновым субагентом-
измерителем** по брифу `invest-dashboard/knowledge/chart_method.md`: `ia images`
выгрузит картинки-кандидаты → субагент классифицирует → числа с графиков
**измеряет кодом** (Pillow/numpy-скрипт, не глазами) → возвращает секцию «ГРАФИКИ
МАТЕРИАЛА» с пометкой «измерено скриптом»/«прочитано глазом». Вплети её в синтез —
измеренные числа сильнее текстовых (воспроизводимы), где расходятся — назови
конфликт. Медленно (~175с/график) — потому в фоне, параллельно ресёрчу.

Дальше:
2. Синтез субагента (текст + секция графиков) — в файл.
3. Внеси в канон **под текущую меру** (`--for-measure`, дефолт = мера профиля):
   ```bash
   $IA add-material ТИКЕР --synthesis /tmp/ТИКЕР-синтез.md \
     --source-name "..." --link "https://..." --for-measure sotp
   ```
4. Продолжай на Шаг 3 — гейт пропустит (материал не старше отчёта и под меру).

**Сменил меру после разбора?** Материал под старую меру больше не удовлетворяет
контракт новой (гейт SPC-017 → узел `material_for_measure`) — перепиши синтез под
новую меру (напр. SOTP требует standalone-оценки частей + сегментные comps,
которых levered не требовал) и внеси заново с нужным `--for-measure`.

Гейт (SPC-015) отказывает `baseline`/`fork` на устаревших данных: «вышел отчёт
{дата}, его разбор не подан». **Единственная законная остановка на человека —
ставка/рост/fcf_base для baseline (Шаг 3), это решение Дениса, а не рутина.**
Кейс LULU (2026-09): без гейта прогон на стейтментах Q1 дал ложное «дёшево»,
хотя Q2 срезал гайденс на −28%; с разбором Q2 baseline перевернулся в
value-trap (65–78 при цене 100).

Для **assumptions-мер** (`levered`/`ev_revenue`/`sotp`) гейт тоже работает, но
`price_context` берётся из `--facts` — **подавай `--facts` вместе с
`--assumptions`** (факты идут только в проверку свежести, не в расчёт).

## Шаг 2.7 — призмы (мера как следствие книг, НЕ роутер-дефолт)

**Мера оценки — осознанное следствие прогона бумаги через призмы книг, а не
случайность роутера.** Роутерная мера из профиля = дефолт-подсказка, которую
надо подтвердить прогоном призм. Порядок важен: призмы честны **только с
информацией** — поэтому этот шаг идёт ПОСЛЕ сбора фактов/материала (Шаг 2–2.5),
а не вслепую.

```bash
$IA prisms ТИКЕР --facts /tmp/ТИКЕР.json
```

Печатает **сток-признаки** (посчитанные из фактов: знак/стабильность FCF,
SBC-ratio, net_cash, has_stakes, research_type) + **каталог 12 призм** из
`knowledge/classifiers/book_prisms.md` (Graham, Fisher, Greenblatt, Pike,
Buffettology, Munger, Marks, Greenwald, Marathon, Thorndike, Quality Investing…):
у каждой — признаки стока → применимость → что предлагает как мера/cross-check.

**Прогони признаки против всех призм** (это чтение аналитика, код не выбирает
за тебя), выбери меру осознанно и запиши вывод в `scope.reason`:

```bash
$IA set ТИКЕР scope '{"measure":"levered","reason":"вывод прогона призм: какие линзы применимы и почему такая мера"}'
$IA confirm ТИКЕР <id>    # confirmed_by заполняется → мера призм-обоснована
```

Кейс CRDO (2026-09): роутер дал `levered` ДО анализа; на калибровке коридор не
попал в цену (2–5× ниже) — только тогда пошли в книги. Правильный порядок —
инфа → призмы → мера. Прогон 12 призм: Quality/Fisher/Buffettology → growth-DCF
long-runway (мера levered верна), скептический слой (Greenwald/Pike/Marks) →
входа нет (priced for perfection). Вывод сохранён в scope.

## Шаг 3 — базовая линия

```bash
$IA baseline ТИКЕР --facts /tmp/ТИКЕР.json \
  --rate 0.17 --growth 0.09 \
  --rate-why "чем обоснована ставка" --growth-why "чем обоснован рост"
```

**Гейт призм (SPC-018) — универсально, для ВСЕХ бумаг.** Перед `baseline`/`fork`
любой меры проверяется, что мера призм-обоснована (`scope.reason` непуст +
`confirmed_by` заполнен) и инфа собрана. Иначе отказ: «мера не обоснована
призмами: cli prisms → выбери меру → set scope → confirm» (или «призмы вслепую»,
если фактов/материала нет). Прошёл Шаг 2.7 — гейт пропустит.

`--rate` и `--growth` **спросить у Дениса**, если он их не назвал: для банка
это стоимость капитала в валюте отчётности и устойчивый рост. Обоснования
уходят в вывод и остаются с оценкой — не выдумывать.

Для небанковских мер (`levered`, `ev_revenue`, `sotp`) вместо `--facts` идёт
`--assumptions` (JSON допущений DCF: `fcf_base`, `shares`, `scenarios.base`
с `growth_path`/`discount_rate`/`terminal_growth`), образцы — в
`agent/eval/fixtures/golden_cases.json`. `collect_facts` даёт net income/eps/
book, но **не `fcf_base`** — его берёшь из cash-flow сам (opcf − capex).

**Отказ — это результат, а не сбой.** Слой останавливает расчёт до числа и
говорит, что запросить из отчётности: рассогласованные валюты, EPS не
сходится с прибылью, устаревший период. Не обходить — исправлять факты.

Расхождение двух мер печатается рядом с коридором: сошлись — оценке можно
верить, разошлись — ширина честно это показывает.

## Шаг 4 — сопоставимые и форки

```bash
$IA peers ТИКЕР -o /tmp/ТИКЕР-peers.json   # полоса сопоставимых
```

Форки-ответ пишешь **ты** (аналитик/модель), по формату `fork.ANSWER_FORMAT`:
каналы (поток/прибыль/дивиденд), якоря каждой величины, тезис + `must_be_true`.
Опирайся на полосу сопоставимых и разобранный материал — не из воздуха. Сложи
в `/tmp/ТИКЕР-forks.json`, затем коридоры считает код:

```bash
$IA fork ТИКЕР --facts /tmp/ТИКЕР.json \
  --rate ... --growth ... --rate-why "..." --growth-why "..." \
  --answer /tmp/ТИКЕР-forks.json
```

Ты предлагаешь предпосылки, **считает код**: границы стоимости не объявляются
руками. Форк заодно печатает **recheck на момент генерации** — если условие
`must_be_true` уже отстаёт от факта, оно помечается.

**Канал форка = по мере.** Банк (`ddm_ri`) → канал `прибыль` (поля
`eps_forward`/`pe_low`/`pe_high`) или `дивиденд`. DCF-меры (`levered`,
`ev_revenue`, `sotp`) → канал **`поток`** (поля `growth_path`/`discount_rate`/
`terminal_growth`; полосу пересчитывает сама мера, low/high задавать не надо).
Названия каналов русские: `поток` / `прибыль` / `дивиденд` — не `cash_flow`.

**Форк по assumptions-мере требует цену явно** (у неё нет банковских фактов с
ценой): добавь `--price ЦЕНА --quote-currency USD`, иначе слой откажет
(«базовая линия цены не несёт»).

## Как читать форк

- **ставка** — величина, несущая тезис, подпёрта источником;
- **НАБЛЮДЕНИЕ** — не подпёрта, доходность от него не считается;
- **границы оценочные** — полоса без источника, коридор шире, чем доказан;
- **ПРЕДУПРЕЖДЕНИЕ: bull ниже базовой линии** — либо метка неверна, либо
  полоса занижает; на живом прогоне так ловилась ошибка в валюте;
- **рынок оплатил N% тезиса** — доля пути от базовой линии к форку; при цене
  ниже базовой линии пишется «тезис не оплачен».

## Ловушки, пойманные на живых прогонах

- **валюта**: величины объявляются в валюте **отчётности**, не котировки.
  Модель дала `dps_forward = 8.0` в долларах при отчётности в тенге —
  коридор вышел 0.32 вместо ~120;
- **канал**: у банка канал «поток» не считается, предпосылок потока у меры
  `ddm_ri` нет. Генератор об этом предупреждает, но если форк ушёл в отказ
  по каналу — это оно;
- **якорь из двух полей**: `own_history` вместе с `confirms=estimate` —
  противоречие, слой отклоняет. Класс говорит, чей источник; `confirms` —
  что именно источник подтверждает (само число, драйвер, либо своя оценка).
  Классы с источником (`company_guide`, `macro_guidance`, `peer_stats`,
  `own_history`) требуют `number` или `driver`; `estimate` — только с
  `analyst_judgement`;
- **проценты вместо долей**: `required_yield = 9.0` вместо `0.09` роняет
  коридор в сто раз (было 1.02 USD вместо ~120). Ставки и темпы — доли,
  мультипликаторы — разы, денежные величины — в валюте отчётности. Ловится
  проверкой направления, но лучше не доводить;
- **расхождение источников по одному факту**: капитал Kaspi за 2К26 в
  эталоне среза 2 827 400 млн ₸, в разборе материала 2 726 402 млн ₸.
  Считать оба и смотреть на сходимость мер: вариант из материала дал 0.0%
  против 1.1%, и ROE из него (39.4%) совпал с измеренным по графику
  (39.14%) — значит он внутренне согласован. Это и есть правило «числа из
  одного отчёта» в работе;
